# 03 — Database schema

SQLite is active today; SQL is kept portable for a later Postgres port (TEXT UUIDs, JSON as TEXT,
INTEGER money). Migrations live in `database/migrations/sqlite/0001..0010` and are applied at startup.

| Migration | Tables / concerns |
| --- | --- |
| 0001 | `users`, `households`, `household_members`, refresh-token / session state, audit fields |
| 0002 | `family_members`, member preferences/exclusions, `household_rules` (type, priority hard/soft, params JSON) |
| 0003 | `categories`, `products`, units/conversions, package sizes, aliases |
| 0004 | `merchants`, `price_observations`, `price_source_posts`, `price_import_batches`, `user_baselines` |
| 0005 | `recipes`, `recipe_ingredients`, `recipe_steps`, `batch_prep_guides` |
| 0006 | `inventory_locations`, `inventory_lots`, `inventory_movements` |
| 0007 | `meal_plans`, `planned_meals`, plan conflicts/explanations |
| 0008 | `shopping_lists`, `shopping_items`, purchases |
| 0009 | `events`, `event_menus`, `event_shopping_items` |
| 0010 | `ai_action_proposals`, `notifications`, `audit_log` |

## Key invariants
- Every domain row has `household_id` (or joins to one); API functions filter by the JWT household.
- Money columns (`amount_minor`, `budget_*_minor`, `estimated_total_minor`, etc.) are INTEGER piasters.
- `price_observations` carry `observation_date`, `source_type`, `batch_id`, `unit_status`,
  `review_status` (`unreviewed`, `needs_unit_confirmation`, `needs_date_confirmation`,
  `needs_product_mapping`, `verified`, `rejected`, `stale`, `estimate`), `reviewed_by/at`.
- `user_baselines` are independent of merchant observations and never overwrite them.
- Dates are ISO `YYYY-MM-DD` strings; timestamps are RFC3339 strings.
- IDs are TEXT UUIDs generated by the application.

## Migration/seed
`belhana_db::migrate` applies migrations in order and records checksums via SQLx. `seed::run` is
idempotent: it checks marker rows (e.g. merchant slug `awlad-zain`) before inserting content.
